# Проектная работа «Веб-ларёк»

«Веб-ларёк» — учебный интернет-магазин товаров для веб-разработчиков. В приложении предусмотрены каталог товаров, просмотр подробной информации о товаре, корзина и оформление заказа. В рамках восьмого спринта реализованы типизация данных, модели данных и коммуникационный слой для работы с API.

Стек: HTML, SCSS, TypeScript, Vite.

## Структура проекта

- `src/` — исходный код приложения;
- `src/components/base/` — базовые классы стартового набора;
- `src/components/Models/` — модели данных;
- `src/components/Communication/` — коммуникационный слой;
- `src/types/index.ts` — типы и интерфейсы приложения;
- `src/utils/` — константы, тестовые данные и утилиты;
- `src/main.ts` — точка входа и проверка работы моделей и API;
- `src/scss/styles.scss` — корневой файл стилей.

## Установка и запуск

Создайте в корне проекта файл `.env`:

```env
VITE_API_ORIGIN=https://larek-api.nomoreparties.co
```

Установите зависимости:

```bash
npm install
```

Запустите проект в режиме разработки:

```bash
npm run dev
```

Сборка проекта:

```bash
npm run build
```

## Архитектура приложения

Приложение проектируется по паттерну MVP (Model-View-Presenter).

- **Model** хранит и изменяет данные приложения. В текущей части проекта к этому слою относятся модели каталога, корзины и покупателя.
- **View** отвечает за отображение данных и пользовательский интерфейс. Компоненты представления будут развиваться в следующей части проекта.
- **Presenter** связывает модели и представления и содержит сценарии взаимодействия между ними. В проекте для слабой связанности предусмотрен брокер событий `EventEmitter`.

Модели данных не зависят от DOM, API и других слоёв. Коммуникационный класс также не встроен в модели: он получает объект, соответствующий интерфейсу `IApi`, через конструктор и использует его посредством композиции.

## Данные

Все добавленные типы приложения находятся в `src/types/index.ts`.

### `TPayment`

```ts
type TPayment = 'card' | 'cash';
```

Описывает доступные способы оплаты заказа.

### `IProduct`

```ts
interface IProduct {
    id: string;
    description: string;
    image: string;
    title: string;
    category: string;
    price: number | null;
}
```

Описывает товар каталога. Поле `price` может быть `null`, если товар недоступен для покупки.

### `IBuyer`

```ts
interface IBuyer {
    payment: TPayment;
    email: string;
    phone: string;
    address: string;
}
```

Описывает полностью заполненные данные покупателя.

### `TBuyerData`

```ts
type TBuyerData = Partial<IBuyer>;
```

Используется моделью покупателя, поскольку поля формы могут заполняться постепенно и независимо друг от друга.

### `TBuyerErrors`

```ts
type TBuyerErrors = Partial<Record<keyof IBuyer, string>>;
```

Описывает объект ошибок валидации данных покупателя. Если поле валидно, соответствующее свойство в объекте ошибок отсутствует.

### `IProductsResponse`

```ts
interface IProductsResponse {
    total: number;
    items: IProduct[];
}
```

Описывает ответ сервера при запросе каталога товаров.

### `TOrder`

```ts
type TOrder = IBuyer & {
    total: number;
    items: string[];
};
```

Описывает объект заказа, который отправляется серверу. В `items` передаются идентификаторы выбранных товаров, а `total` содержит итоговую стоимость заказа.

### `IOrderResponse`

```ts
interface IOrderResponse {
    id: string;
    total: number;
}
```

Описывает ответ сервера после успешного оформления заказа.

### `IApi`

```ts
interface IApi {
    get<T extends object>(uri: string): Promise<T>;
    post<T extends object>(uri: string, data: object, method?: ApiPostMethods): Promise<T>;
}
```

Описывает программный интерфейс клиента API. Коммуникационный слой зависит от этого интерфейса, а не от конкретной реализации `Api`.

## Базовые классы

### `Component<T>`

Абстрактный базовый класс компонентов представления.

**Конструктор**

`constructor(container: HTMLElement)` — принимает корневой DOM-элемент компонента.

**Поля**

- `container: HTMLElement` — корневой DOM-элемент компонента.

**Методы**

- `render(data?: Partial<T>): HTMLElement` — присваивает переданные данные экземпляру компонента и возвращает корневой DOM-элемент;
- `setImage(element: HTMLImageElement, src: string, alt?: string): void` — устанавливает изображению `src` и при необходимости `alt`.

### `Api`

Базовый HTTP-клиент. Реализует интерфейс `IApi`.

**Конструктор**

`constructor(baseUrl: string, options: RequestInit = {})` — принимает базовый URL и необязательные настройки запросов.

**Поля**

- `baseUrl: string` — базовый адрес сервера;
- `options: RequestInit` — общие настройки запросов.

**Методы**

- `get<T extends object>(uri: string): Promise<T>` — выполняет GET-запрос;
- `post<T extends object>(uri: string, data: object, method?: ApiPostMethods): Promise<T>` — выполняет POST/PUT/DELETE-запрос с JSON-телом;
- `handleResponse<T>(response: Response): Promise<T>` — защищённый метод обработки ответа сервера.

### `EventEmitter`

Брокер событий, реализующий интерфейс `IEvents`. Используется для слабосвязанного взаимодействия частей приложения.

**Конструктор**

`constructor()` — создаёт пустую коллекцию подписчиков.

**Поля**

- `_events: Map<EventName, Set<Subscriber>>` — хранит наборы обработчиков для событий.

**Методы**

- `on<T extends object>(eventName: EventName, callback: (event: T) => void): void` — подписывает обработчик на событие;
- `off(eventName: EventName, callback: Subscriber): void` — удаляет обработчик события;
- `emit<T extends object>(eventName: string, data?: T): void` — инициирует событие;
- `onAll(callback: (event: EmitterEvent) => void): void` — подписывает обработчик на все события;
- `offAll(): void` — удаляет все подписки;
- `trigger<T extends object>(eventName: string, context?: Partial<T>): (data: T) => void` — создаёт функцию-триггер для события.

## Модели данных

### `Products`

Модель каталога товаров. Отвечает только за хранение списка товаров и товара, выбранного для подробного просмотра.

**Конструктор**

Конструктор не принимает параметров. Начальное состояние: пустой каталог и отсутствие выбранного товара.

**Поля**

- `items: IProduct[]` — массив товаров каталога;
- `selectedItem: IProduct | null` — товар, выбранный для подробного отображения.

**Методы**

- `setItems(items: IProduct[]): void` — сохраняет массив товаров;
- `getItems(): IProduct[]` — возвращает копию массива товаров;
- `getItem(id: string): IProduct | undefined` — возвращает товар с указанным идентификатором;
- `setSelectedItem(item: IProduct | null): void` — сохраняет выбранный товар или очищает выбор;
- `getSelectedItem(): IProduct | null` — возвращает выбранный товар.

### `Basket`

Модель корзины. Хранит товары, выбранные пользователем для покупки, и выполняет операции над корзиной.

**Конструктор**

Конструктор не принимает параметров. Начальное состояние: пустая корзина.

**Поля**

- `items: IProduct[]` — массив товаров в корзине.

**Методы**

- `getItems(): IProduct[]` — возвращает копию массива товаров корзины;
- `addItem(item: IProduct): void` — добавляет товар, если его ещё нет в корзине;
- `removeItem(item: IProduct): void` — удаляет товар по его `id`;
- `clear(): void` — полностью очищает корзину;
- `getTotalPrice(): number` — возвращает общую стоимость товаров. Цена `null` учитывается как `0`;
- `getItemsCount(): number` — возвращает количество товаров;
- `hasItem(id: string): boolean` — проверяет наличие товара в корзине по идентификатору.

### `Buyer`

Модель данных покупателя. Позволяет постепенно сохранять поля оформления заказа, получать и очищать данные, а также валидировать заполнение.

**Конструктор**

Конструктор не принимает параметров. Начальное состояние: данные покупателя отсутствуют.

**Поля**

- `data: TBuyerData` — частично заполненные данные покупателя.

**Методы**

- `setData(data: TBuyerData): void` — объединяет переданные значения с уже сохранёнными, не удаляя остальные поля;
- `getData(): TBuyerData` — возвращает копию текущих данных покупателя;
- `clear(): void` — очищает все данные покупателя;
- `validate(): TBuyerErrors` — проверяет поля на непустое значение и возвращает объект ошибок. Отсутствие свойства в объекте ошибок означает, что соответствующее поле валидно.

## Слой коммуникации

### `WebLarekApi`

Класс предметного API приложения. Отвечает за запрос каталога и отправку заказа. Не наследуется от `Api`: использует композицию и зависит только от интерфейса `IApi`.

**Конструктор**

`constructor(api: IApi)` — принимает объект, реализующий методы `get` и `post` интерфейса `IApi`.

**Поля**

- `api: IApi` — клиент для выполнения HTTP-запросов.

**Методы**

- `getProducts(): Promise<IProductsResponse>` — выполняет GET-запрос на `/product/` и возвращает объект с массивом товаров;
- `createOrder(order: TOrder): Promise<IOrderResponse>` — выполняет POST-запрос на `/order/`, передаёт данные заказа и возвращает подтверждение покупки.

## Проверка работы в `main.ts`

В `main.ts` создаются экземпляры `Products`, `Basket` и `Buyer`. Все публичные методы моделей вызываются на тестовых данных, а результаты выводятся в консоль с поясняющими сообщениями.

После локальных проверок создаются экземпляры `Api` и `WebLarekApi`. Через `WebLarekApi.getProducts()` выполняется запрос каталога с сервера. Полученный массив сохраняется методом `Products.setItems()`, после чего сохранённый каталог выводится в консоль методом `Products.getItems()`.
